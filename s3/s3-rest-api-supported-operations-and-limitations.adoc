= Operaciones compatibles de la API de REST de S3 y limitaciones en StorageGRID
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
El sistema StorageGRID implementa la API de Simple Storage Service (API versión 2006-03-01) con soporte para la mayoría de las operaciones y con algunas limitaciones. Necesitas entender los detalles de la implementación cuando integras aplicaciones cliente de la API de REST de S3.

El sistema StorageGRID admite tanto solicitudes de tipo virtual hosted como solicitudes de tipo path.



[[date-handling]]
== Manejo de fechas

La implementación de la API de REST de S3 en StorageGRID solo admite formatos de fecha HTTP válidos.

El sistema StorageGRID solo admite formatos de fecha HTTP válidos para cualquier encabezado que acepte valores de fecha. La parte horaria de la fecha puede especificarse en formato de hora media de Greenwich (GMT) o en formato de hora universal coordinada (UTC) sin desfase horario (+0000 debe especificarse). Si incluyes el encabezado  `x-amz-date` en tu solicitud, este reemplaza cualquier valor especificado en el encabezado Date de la solicitud. Cuando usas AWS Signature Version 4, el encabezado  `x-amz-date` debe estar presente en la solicitud firmada porque el encabezado de fecha no es compatible.



[[common-request-headers]]
== Encabezados de solicitud habituales

El sistema StorageGRID admite los encabezados de solicitud habituales definidos por https://docs.aws.amazon.com/AmazonS3/latest/API/RESTCommonRequestHeaders.html["${post_edited_translations.segment}"^], con una excepción.

[cols="1a,2a"]
|===
| Encabezado de la solicitud | Implementación 


 a| 
Autorización
 a| 
Compatibilidad total con AWS Signature Version 2

Compatibilidad con AWS Signature Version 4, con las siguientes excepciones:

* Cuando proporcionas el valor real de la suma de comprobación de la carga útil en `x-amz-content-sha256`, el valor se acepta sin validación, como si el valor `UNSIGNED-PAYLOAD` se hubiera proporcionado para el encabezado. Cuando proporcionas un valor de encabezado `x-amz-content-sha256` que implica `aws-chunked` streaming (por ejemplo, STREAMING-AWS4-HMAC-SHA256-PAYLOAD), las firmas de los fragmentos no se verifican con respecto a los datos de los fragmentos.


|===

x-amz-id-2
