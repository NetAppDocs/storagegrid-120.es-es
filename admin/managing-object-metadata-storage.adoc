= Administra el almacenamiento de metadatos de objetos en StorageGRID
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
La capacidad de metadatos de objetos de un sistema StorageGRID controla el número máximo de objetos que se pueden almacenar en ese sistema. Para asegurarte de que tu sistema StorageGRID tenga espacio suficiente para almacenar objetos nuevos, debes comprender dónde y cómo almacena StorageGRID los metadatos de objetos.



[[what-is-object-metadata]]
== ¿Qué son los metadatos de un objeto?

Los metadatos de objetos son cualquier información que describe un objeto. StorageGRID utiliza los metadatos de objetos para realizar el seguimiento de las ubicaciones de todos los objetos en todo el grid y gestionar el ciclo de vida de cada objeto a lo largo del tiempo.

${post_edited_translations.segment}

* ${post_edited_translations.segment}
* Cualquier par clave-valor de metadatos de usuario personalizados asociados al objeto.
* Para los objetos de S3, cualquier par clave-valor de etiquetas asociado con el objeto.
* En el caso de las copias replicadas de objetos, la ubicación de almacenamiento actual de cada copia.
* ${post_edited_translations.segment}
* Para las copias de objetos en un Cloud Storage Pool, la ubicación del objeto, incluyendo el nombre del bucket externo y el identificador único del objeto.
* ${post_edited_translations.segment}




[[how-is-object-metadata-stored]]
== ${post_edited_translations.segment}

StorageGRID mantiene los metadatos de los objetos en una base de datos Cassandra, que se almacena de forma independiente de los datos de los objetos. Para proporcionar redundancia y proteger los metadatos de los objetos frente a pérdidas, StorageGRID almacena tres copias de los metadatos de todos los objetos del sistema en cada sitio.

Esta figura representa los nodos de almacenamiento en dos sitios. Cada sitio tiene la misma cantidad de metadatos de objetos, y los metadatos de cada sitio se subdividen entre todos los nodos de almacenamiento de ese sitio.

image:metadata_space_across_sites.png["Espacio de metadatos en todos los sitios"]



[[where-is-object-metadata-stored]]
== ${post_edited_translations.segment}

Esta figura representa los volúmenes de almacenamiento de un único nodo de almacenamiento.

image:metadata_space_storage_node.png["Nodo de almacenamiento de metadatos"]

Como se muestra en la figura, StorageGRID reserva espacio para los metadatos de objetos en el volumen de almacenamiento 0 de cada Storage Node. Utiliza el espacio reservado para almacenar metadatos de objetos y realizar operaciones esenciales de la base de datos. El espacio restante en el volumen de almacenamiento 0 y todos los demás volúmenes de almacenamiento del Storage Node se utilizan exclusivamente para datos de objetos (copias replicadas y fragmentos con codificación de borrado).

${post_edited_translations.segment}

[[actual-reserved-space-for-metadata]]
== Espacio realmente reservado para metadatos

A diferencia de la configuración de espacio reservado para metadatos a nivel de sistema, el _espacio reservado real_ para los metadatos de los objetos se determina para cada Storage Node. Para cualquier Storage Node, el espacio reservado real para metadatos depende del tamaño del volumen 0 de ese nodo y de la configuración de espacio reservado para metadatos a nivel de sistema.

[[example-for-actual-reserved-metadata-space]]
=== Ejemplo de espacio real reservado para metadatos

Supongamos que instalas un nuevo sistema StorageGRID con la versión 11.7 o posterior. Para este ejemplo, supón que cada Storage Node tiene más de 128 GB de RAM y que el volumen 0 de Storage Node 1 (SN1) es de 6 TB. Según estos valores:

* El *espacio reservado para metadatos* de todo el sistema está configurado en 8 TB. (Este es el valor predeterminado para una nueva instalación de StorageGRID 11.6 o superior si cada Storage Node tiene más de 128 GB de RAM).
* El espacio realmente reservado para los metadatos de SN1 es de 6 TB. (Se reserva todo el volumen porque el volumen 0 es más pequeño que la configuración de *Espacio reservado para metadatos*.)

[[how-storage-nodes-of-different-sizes-affect-object-capacity]]
== Cómo influyen los nodos de almacenamiento de distintos tamaños en la capacidad de los objetos

Como se describió anteriormente, StorageGRID distribuye de manera uniforme los metadatos de objetos entre los nodos de almacenamiento de cada sitio. Por este motivo, si un sitio contiene nodos de almacenamiento de diferentes tamaños, el nodo más pequeño del sitio determina la capacidad de metadatos del sitio.

${post_edited_translations.segment}

* Tienes una red de un único sitio que contiene tres nodos de almacenamiento de distintos tamaños.
* La opción *Espacio reservado para metadatos* está configurada en 4 TB.

Como los metadatos de objetos se distribuyen de manera uniforme entre los nodos de almacenamiento de un sitio, cada nodo de este ejemplo solo puede albergar 1,32 TB de metadatos. No se pueden usar los 0,66 TB adicionales de espacio de metadatos permitido para SN2 y SN3.

image:metadata_space_three_storage_nodes.png["Espacio de metadatos tres nodos de almacenamiento"]

Del mismo modo, porque StorageGRID mantiene todos los metadatos de los objetos de un sistema StorageGRID en cada sitio, la capacidad total de metadatos de un sistema StorageGRID se determina por la capacidad de metadatos de objetos del sitio más pequeño.

Y dado que la capacidad de metadatos de los objetos determina el número máximo de objetos, cuando un nodo agota su capacidad de metadatos, la grid está, en efecto, llena.
