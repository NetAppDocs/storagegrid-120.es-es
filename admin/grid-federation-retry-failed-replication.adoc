= Identifica y vuelve a intentar las operaciones de replicación fallidas de StorageGRID
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
Después de resolver la alerta *Cross-grid replication permanent failure*, debes comprobar si hay algún objeto o marcador de eliminación que no se haya replicado en la otra grid. Luego puedes volver a ingresar estos objetos o usar la Grid Management API para volver a intentar la replicación.

La alerta *«Fallo permanente en la replicación entre redes»* indica que los objetos del inquilino no se pueden replicar entre los buckets de dos redes por un motivo que requiere la intervención del usuario para resolverse. Esta alerta suele deberse a un cambio en el bucket de origen o en el de destino. Para obtener más información, consulta link:grid-federation-troubleshoot.html["Solucionar errores de federación de grid"].



[[determine-if-any-objects-failed-to-be-replicated]]
== Determina si algún objeto no se replicó

Para determinar si hay algún objeto o marcador de eliminación que no se haya replicado en la otra grid, puedes buscar en el registro de auditoría los mensajes link:../audit/cgrr-cross-grid-replication-request.html["CGRR (Solicitud de replicación entre grids)"]. Este mensaje se añade al registro cuando StorageGRID no consigue replicar un objeto, un objeto multiparte o un marcador de eliminación al bucket de destino.

Puedes usar la link:../audit/using-audit-explain-tool.html["herramienta audit-explain"] para traducir los resultados a un formato más fácil de leer.

.Antes de empezar
* Tienes permiso de acceso root.
* Tienes el archivo  `Passwords.txt`.
* Conoces la dirección IP del nodo de administración principal.


.Pasos
. Inicia sesión en el nodo de administración principal:
+
.. Introduce el siguiente comando: `ssh admin@_primary_Admin_Node_IP_`
.. Introduce la contraseña que figura en el archivo  `Passwords.txt`.
.. Introduce el siguiente comando para pasar a ser usuario root: `su -`
.. Introduce la contraseña que figura en el archivo  `Passwords.txt`.
+
Cuando inicias sesión como root, el indicador cambia de  `$` a  `#`.



. Busca mensajes CGRR en el archivo audit.log y usa la herramienta audit-explain para dar formato a los resultados.
+
Por ejemplo, este comando busca con «grep» todos los mensajes CGRR de los últimos 30 minutos y utiliza la herramienta «audit-explain».

+
`# awk -vdate=$(date -d "30 minutes ago" '+%Y-%m-%dT%H:%M:%S') '$1$2 >= date { print }' audit.log | grep CGRR | audit-explain`

+
Los resultados del comando tendrán un aspecto similar al de este ejemplo, que contiene entradas correspondientes a seis mensajes CGRR. En el ejemplo, todas las solicitudes de replicación entre grids devolvieron un error general porque no se pudo replicar el objeto. Los tres primeros errores son de operaciones de "replicate object", y los tres últimos errores son de operaciones de "replicate delete marker".

[[retry-failed-replications]]
== Reintentar las replicaciones fallidas

Después de generar una lista de los objetos y marcadores de eliminación que no se replicaron en el bucket de destino y resolver los problemas subyacentes, puedes volver a intentar la replicación de dos maneras:

* Vuelve a introducir cada objeto en el bucket de origen.
* Utiliza la API privada de gestión de la grid, tal y como se describe.


.Pasos
. En la parte superior del Grid Manager, selecciona el icono de ayuda y selecciona *API documentation*.
. Selecciona *Ir a la documentación privada de la API*.
+

NOTE: Los puntos finales de la API de StorageGRID marcados como «Privados» están sujetos a cambios sin previo aviso. Los puntos finales privados de StorageGRID también ignoran la versión de la API de la solicitud.

. En la sección *cross-grid-replication-advanced*, selecciona el siguiente endpoint:
+
`POST /private/cross-grid-replication-retry-failed`

. Selecciona *Pruébalo*.
. En el cuadro de texto *body*, reemplaza la entrada de ejemplo de *versionID* por un identificador de versión del audit.log que corresponda a una solicitud de replicación entre grids que haya fallado.
+
Asegúrate de mantener las comillas dobles alrededor de la cadena.

. Selecciona *Ejecutar*.
. Comprueba que el código de respuesta del servidor sea *204*, lo que indica que el objeto o el marcador de eliminación se ha marcado como pendiente para la replicación entre grids hacia el otro grid.
+

NOTE: «Pendiente» significa que la solicitud de replicación entre grids se ha añadido a la cola interna para su procesamiento.





[[monitor-replication-retries]]
== Supervisar los reintentos de replicación

Debes supervisar las operaciones de reintento de replicación para asegurarte de que se completan.


TIP: Puede que la replicación de un objeto o de un marcador de eliminación en la otra grid tarde varias horas o incluso más.

Puedes supervisar las operaciones de reintento de dos formas:

* Utiliza una solicitud S3 link:../s3/head-object.html["HeadObject"] o link:../s3/get-object.html["GetObject"]. La respuesta incluye el encabezado de respuesta específico de StorageGRID  `x-ntap-sg-cgr-replication-status`, que tendrá uno de los siguientes valores:
+
[cols="1a,2a"]
|===
| Grid | Estado de la replicación 


 a| 
Fuente
 a| 
** *FINALIZADO*: La replicación se realizó con éxito.
** *PENDIENTE*: El objeto aún no se ha replicado.
** *ERROR*: La replicación falló debido a un error permanente. Un usuario debe solucionar el error.




 a| 
Destino
 a| 
*RÉPLICA*: El objeto fue replicado desde la cuadrícula de origen.

|===
* Utiliza la API privada de gestión de la grid, tal y como se describe.


.Pasos
. En la sección *cross-grid-replication-advanced* de la documentación de la API privada, selecciona el siguiente endpoint:
+
`GET /private/cross-grid-replication-object-status/{id}`

. Selecciona *Pruébalo*.
. En la sección de Parámetros, introduce el ID de versión que usaste en la solicitud  `cross-grid-replication-retry-failed`.
. Selecciona *Ejecutar*.
. Comprueba que el código de respuesta del servidor sea *200*.
. Comprueba el estado de la replicación, que será uno de los siguientes:
+
** *PENDIENTE*: El objeto aún no se ha replicado.
** *FINALIZADO*: La replicación se realizó con éxito.
** *FALLO*: La replicación falló debido a un error permanente. Un usuario debe solucionar el error.
