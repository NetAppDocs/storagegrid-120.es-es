= Conoce StorageGRID branch buckets
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
Un «branch bucket» permite acceder a los objetos de un bucket tal y como estaban en un momento determinado.

Creas un bucket de ramificación a partir de un bucket existente. Una vez que creas un bucket de ramificación, el bucket original a partir del cual se creó se denomina _bucket base_. Además, puedes crear un bucket de ramificación a partir de otro bucket de ramificación.

Un bucket de ramificación proporciona acceso a los datos protegidos, pero no sirve como copia de seguridad. Para seguir protegiendo los datos, usa estas funciones en los buckets base:

* link:../tenant/using-s3-object-lock.html["Bloqueo de objetos de S3"]
* link:../admin/grid-federation-what-is-cross-grid-replication.html["Replicación entre grids"] para buckets base
* link:../tenant/manage-bucket-policy.html["Políticas de buckets"] para buckets con control de versiones para limpiar las versiones antiguas de los objetos


Ten en cuenta las siguientes características de los cubos de ramificación:

* Puedes acceder a los objetos de los buckets de las ramas utilizando link:../tenant/use-s3-console.html["Consola de S3 para descargar objetos"].
* Cuando los clientes acceden a objetos en un bucket rama, link:../s3/use-access-policies.html["políticas de acceso"] del bucket rama, en lugar de las políticas del bucket base, determinan si se concede o se deniega el acceso.
* Los objetos creados en un bucket base se evalúan en función de cómo se aplican link:../ilm/access-create-ilm-rule-wizard.html["Reglas de ILM"] al bucket base. Los objetos creados en un bucket de rama se evalúan en función de cómo se aplican las reglas de ILM al bucket de rama.
* La replicación entre grids no es compatible con los buckets de sucursales.
* Los servicios de plataforma no son compatibles con los buckets de sucursales.




[[examples-for-branch-bucket-usage]]
== Ejemplos de uso de los branch buckets

* Puedes usar un bucket de rama para eliminar objetos corruptos creando un bucket de rama desde un punto en el tiempo anterior a que ocurriera la corrupción y luego apuntar las aplicaciones al bucket de rama en lugar de al bucket base que contiene los objetos corruptos.
* Estás almacenando datos en un bucket con control de versiones. Hubo una vulnerabilidad accidental que provocó que se ingresaran muchos objetos no deseados después del momento _T_. Puedes crear un bucket de rama para el valor Before time, _T_, y redirigir las operaciones de los clientes a ese bucket de rama. Así, solo los objetos ingresados antes del momento Before time _T_ estarán disponibles para los clientes.




[[operations-on-objects-in-branch-buckets]]
== Operaciones con objetos en los buckets de rama

* Una operación PUT de objeto en un bucket de rama crea un objeto en la rama.
* Una operación GET sobre un objeto en un bucket de rama recupera un objeto de la rama. Si el objeto no existe en el bucket de rama, el objeto se recupera del bucket base.
* La eliminación de objetos de los buckets de las ramas ocurre de la siguiente manera:

 a|

 a|

 a| 
HEAD/GET devuelve que el objeto existe, y aún se puede acceder a versiones específicas
