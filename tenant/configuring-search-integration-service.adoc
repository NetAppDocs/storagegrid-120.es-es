= Configura el servicio de integración de búsqueda en StorageGRID
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
Habilitas la integración de búsqueda para un bucket creando un XML de integración de búsqueda y usando el Tenant Manager para aplicar el XML al bucket.

.Antes de empezar
* Los servicios de la plataforma fueron habilitados para tu cuenta de inquilino por un administrador de StorageGRID.
* Ya has creado un bucket de S3 cuyo contenido quieres indexar.
* El punto final que pretendes utilizar como destino para el servicio de integración de búsquedas ya existe y tienes su URN.
* Perteneces a un grupo de usuarios que tiene el link:tenant-management-permissions.html["Gestiona todos los buckets o permiso de acceso a raíz"]. Estos permisos anulan la configuración de permisos de las políticas de grupo o de bucket al configurar el bucket mediante Tenant Manager.


.Acerca de esta tarea
Después de que configuras el servicio de integración de búsqueda para un bucket de origen, crear un objeto o actualizar los metadatos o las etiquetas de un objeto hace que los metadatos del objeto se envíen al endpoint de destino.

Si habilitas el servicio de integración de búsqueda para un bucket que ya contiene objetos, las notificaciones de metadatos no se envían automáticamente para los objetos existentes. Actualiza estos objetos existentes para asegurarte de que sus metadatos se agreguen al índice de búsqueda de destino.

.Pasos
. Habilita la integración de búsqueda para un bucket:
+
** Utiliza un editor de texto para crear el archivo XML de notificación de metadatos necesario para habilitar la integración de búsqueda.
** Al configurar el XML, utiliza el URN de un punto final de integración de búsqueda como destino.
+
Los objetos se pueden filtrar según el prefijo de su nombre. Por ejemplo, se pueden enviar los metadatos de los objetos con el prefijo `images` a un destino, y los metadatos de los objetos con el prefijo `videos` a otro. Las configuraciones que contengan prefijos que se solapen no son válidas y se rechazan al enviarlas. Por ejemplo, no se permite una configuración que incluya una regla para objetos con el prefijo `test` y una segunda regla para objetos con el prefijo `test2`.

+
Si es necesario, consulta la <<example-notification-config,Ejemplos para la configuración XML de metadatos>>.

+
[listing]
----
<MetadataNotificationConfiguration>
 <Rule>
    <Status>Enabled</Status>
    <Prefix></Prefix>
    <Destination>
       <Urn>/Urn>
       </Destination>
 </Rule>
</MetadataNotificationConfiguration>
----
+
Elementos en el archivo XML de configuración de la notificación de metadatos:

+
[cols="1a,3a,1a"]
|===
| Nombre | Descripción | Requerido 


 a| 
MetadataNotificationConfiguration
 a| 
Etiqueta de contenedor para las reglas que se utilizan para especificar los objetos y el destino de las notificaciones de metadatos.

Contiene uno o varios elementos «Rule».
 a| 
Sí



 a| 
Regla
 a| 
Etiqueta de contenedor para una regla que identifica los objetos cuyos metadatos deben añadirse a un índice específico.

Se rechazan las reglas cuyos prefijos se solapan.

Incluido en el elemento MetadataNotificationConfiguration.
 a| 
Sí



 a| 
ID
 a| 
Identificador único de la regla.

Incluido en el elemento Rule.
 a| 
No



 a| 
Estado
 a| 
El estado puede ser «Activado» o «Desactivado». No se realiza ninguna acción para las reglas que están desactivadas.

Incluido en el elemento Rule.
 a| 
Sí



 a| 
Prefijo
 a| 
Los objetos que coinciden con el prefijo se ven afectados por la regla y sus metadatos se envían al destino especificado.

Para que coincidan todos los objetos, especifica un prefijo vacío.

Incluido en el elemento Rule.
 a| 
Sí



 a| 
Destino
 a| 
Etiqueta de contenedor para el destino de una regla.

Incluido en el elemento Rule.
 a| 
Sí



 a| 
Urna
 a| 
URN del destino al que se envían los metadatos del objeto. Debe ser el URN de un endpoint de StorageGRID con las siguientes propiedades:

*** `es` debe ser el tercer elemento.
*** El URN debe terminar con el índice y el tipo en los que se almacenan los metadatos, en el formato `domain-name/myindex/mytype`.


Los puntos finales se configuran mediante el Tenant Manager o la Tenant Management API. Tienen el siguiente formato:

*** `arn:aws:es:region:account-ID:domain/mydomain/myindex/mytype`
*** `urn:mysite:es:::mydomain/myindex/mytype`


El endpoint debe configurarse antes de enviar el archivo XML de configuración o la configuración fallará con un error 404.

El URN se incluye en el elemento Destination.
 a| 
Sí

|===


. En el Gestor de inquilinos, selecciona *STORAGE (S3)* > *Buckets*.
. Selecciona el nombre del depósito de origen.
+
Aparece la página de detalles del bucket.

. Selecciona *Platform services* > *Search integration*
. Marca la casilla *Habilitar integración de búsqueda*.
. Pega la configuración de la notificación de metadatos en el cuadro de texto y selecciona *Guardar cambios*.
+

NOTE: Un administrador de StorageGRID debe habilitar los servicios de la plataforma para cada cuenta de inquilino mediante Grid Manager o Management API. Ponte en contacto con tu administrador de StorageGRID si se produce un error al guardar el archivo XML de configuración.

. Comprueba que el servicio de integración de búsqueda esté configurado correctamente:
+
.. Añade un objeto al depósito de origen que cumpla los requisitos para activar una notificación de metadatos según lo especificado en el archivo XML de configuración.
+
En el ejemplo mostrado anteriormente, todos los objetos añadidos al bucket activan una notificación de metadatos.

.. Comprueba que se haya añadido al índice de búsqueda especificado en el endpoint un documento JSON que contenga los metadatos y las etiquetas del objeto.




.Después de que termines
Si es necesario, puedes desactivar la integración de búsqueda para un bucket utilizando cualquiera de los siguientes métodos:

* Selecciona *STORAGE (S3)* > *Buckets* y desmarca la casilla *Enable search integration*.
* Si utilizas la API de S3 directamente, usa una solicitud de notificación de metadatos de DELETE Bucket. Consulta las instrucciones para implementar aplicaciones cliente de S3.




[[example-notification-configexample-metadata-notification-configuration-that-applies-to-all-objects]]
== [[example-notification-config]]Ejemplo: configuración de notificaciones de metadatos que se aplica a todos los objetos

En este ejemplo, los metadatos de todos los objetos se envían al mismo destino.

[listing]
----
<MetadataNotificationConfiguration>
    <Rule>
        <ID>Rule-1</ID>
        <Status>Enabled</Status>
        <Prefix></Prefix>
        <Destination>
           <Urn>urn:myes:es:::sgws-notifications/test1/all</Urn>
        </Destination>
    </Rule>
</MetadataNotificationConfiguration>
----


[[example-metadata-notification-configuration-with-two-rules]]
== Ejemplo: configuración de la notificación de metadatos con dos reglas

En este ejemplo, los metadatos de los objetos que coinciden con el prefijo `/images` se envían a un destino, mientras que los metadatos de los objetos que coinciden con el prefijo `/videos` se envían a un segundo destino.

[listing]
----

<MetadataNotificationConfiguration>
    <Rule>
        <ID>Images-rule</ID>
        <Status>Enabled</Status>
        <Prefix>/images</Prefix>
        <Destination>
           <Urn>arn:aws:es:us-east-1:3333333:domain/es-domain/graphics/imagetype</Urn>
        </Destination>
    </Rule>
    <Rule>
        <ID>Videos-rule</ID>
        <Status>Enabled</Status>
        <Prefix>/videos</Prefix>
        <Destination>
           <Urn>arn:aws:es:us-west-1:22222222:domain/es-domain/graphics/videotype</Urn>
        </Destination>
    </Rule>
</MetadataNotificationConfiguration>
----


[[metadata-notification-format]]
== Formato de notificación de metadatos

Al habilitar el servicio de integración de búsqueda para un bucket, se genera un documento JSON y se envía al endpoint de destino cada vez que se añaden, actualizan o eliminan metadatos o etiquetas de un objeto.

Este ejemplo muestra un ejemplo del JSON que se podría generar cuando se crea un objeto con la clave  `SGWS/Tagging.txt` en un bucket llamado  `test`. El bucket  `test` no está versionado, así que la etiqueta  `versionId` está vacía.

[listing]
----
{
  "bucket": "test",
  "key": "SGWS/Tagging.txt",
  "versionId": "",
  "accountId": "86928401983529626822",
  "size": 38,
  "md5": "3d6c7634a85436eee06d43415012855",
  "region":"us-east-1",
  "metadata": {
    "age": "25"
  },
  "tags": {
    "color": "yellow"
  }
}
----


[[fields-included-in-the-json-document]]
=== Campos incluidos en el documento JSON

El nombre del documento incluye el nombre del bucket, el nombre del objeto y el ID de versión, si lo hay.

Información del bucket y del objeto::
+
--
`bucket`: nombre del depósito

`key`: nombre de la clave del objeto

`versionID`: versión del objeto, para objetos en depósitos con control de versiones

`region`: región del bucket, por ejemplo `us-east-1`

--
Metadatos del sistema::
+
--
`size`: tamaño del objeto (en bytes) tal como lo ve un cliente HTTP

`md5`: hash de objeto

--
Metadatos del usuario::
+
--
`metadata`: todos los metadatos de usuario para el objeto, como pares clave-valor

`key:value`

--
Etiquetas::
+
--
`tags`: Todas las etiquetas de objeto definidas para el objeto, en forma de pares clave-valor

`key:value`

--




[[how-to-view-results-in-elasticsearch]]
=== Cómo consultar los resultados en Elasticsearch

Para las etiquetas y los metadatos de usuario, StorageGRID pasa las fechas y los números a Elasticsearch como cadenas o como notificaciones de eventos de S3. Para configurar Elasticsearch para que interprete estas cadenas como fechas o números, sigue las instrucciones de Elasticsearch para la asignación dinámica de campos y para la asignación de formatos de fecha. Habilita las asignaciones de campos dinámicos en el índice antes de configurar el servicio de integración de búsqueda. Una vez indexado un documento, no puedes editar los tipos de campo del documento en el índice.
