= Crear un bucket S3 de StorageGRID
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
${post_edited_translations.segment}

.Antes de empezar
* Has iniciado sesión en el Tenant Manager con un link:../admin/web-browser-requirements.html["navegador web compatible"].
* Perteneces a un grupo de usuarios que tiene acceso Root o la autorización Manage all buckets link:tenant-management-permissions.html["${post_edited_translations.segment}"]. Estos permisos anulan la configuración de permisos en las políticas de grupo o de bucket.
+

NOTE: Los permisos para establecer o modificar las propiedades de S3 Object Lock de buckets u objetos se pueden conceder mediante link:../s3/use-access-policies.html["política de bucket o política de grupo"].

* Si tienes previsto habilitar S3 Object Lock para un bucket, un administrador de la grid ha habilitado la configuración global de S3 Object Lock para el sistema StorageGRID y has revisado los requisitos para los buckets y objetos de S3 Object Lock.
* Si cada inquilino va a tener 5,000 buckets, cada Storage Node en la grid tiene un mínimo de 64 GB de RAM.
+

NOTE: Cada grid puede tener un máximo de 100,000 buckets, incluyendo link:../tenant/what-is-branch-bucket.html["cubos de rama"].





[[access-the-wizard]]
== Accede al asistente

.Pasos
. Selecciona *View buckets* desde el panel, o selecciona *STORAGE (S3)* > *Buckets*.
. Selecciona *Create bucket*.




[[enter-details]]
== Introduce los datos

.Pasos
. Introduce los datos del bucket.
+
[cols="1a,3a"]
|===
| Campo | Descripción 


 a| 
Nombre del bucket
 a| 
Un nombre para el bucket que cumpla estas reglas:

** Debe ser único en cada sistema StorageGRID (no solo dentro de la cuenta del inquilino).
** Debe ser compatible con DNS.
** Debe contener al menos 3 y no más de 63 caracteres.
** ${post_edited_translations.segment}
** No debe contener puntos en las solicitudes de tipo virtual hosted style. Los puntos provocarán problemas con la verificación del certificado comodín del servidor.


Para más información, consulta el https://docs.aws.amazon.com/AmazonS3/latest/userguide/bucketnamingrules.html["${post_edited_translations.segment}"^].

*Nota*: No puedes cambiar el nombre del bucket después de crearlo.



 a| 
Región
 a| 
La región del bucket.

Tu administrador de StorageGRID gestiona las regiones disponibles. La región de un bucket puede afectar a la política de protección de datos que se aplica a los objetos. Por defecto, todos los buckets se crean en la  `us-east-1` región. Si la región por defecto está configurada en una región distinta de  `us-east-1`, esta otra región aparecerá seleccionada inicialmente en el menú desplegable.

${post_edited_translations.segment}

|===
. Selecciona *Continuar*.




[[manage-settings]]
== Gestiona la configuración

.Pasos
. ${post_edited_translations.segment}
+
Activa el versionado de objetos si quieres almacenar cada versión de cada objeto en este bucket. Después podrás recuperar las versiones anteriores de un objeto según lo necesites.

+
Debes activar el control de versiones de los objetos si:

+
** ${post_edited_translations.segment}
** Quieres crear un link:../tenant/what-is-branch-bucket.html["bucket de rama"] desde este bucket.


. Si la configuración global de S3 Object Lock está activada, puedes activar opcionalmente S3 Object Lock para el bucket para almacenar objetos usando un modelo de escritura única y lectura múltiple (WORM).
+
Activa S3 Object Lock para un bucket solo si necesitas conservar los objetos durante un periodo de tiempo fijo, por ejemplo, para cumplir con ciertos requisitos normativos. S3 Object Lock es una configuración permanente que te ayuda a evitar que los objetos se eliminen o se sobrescriban durante un periodo de tiempo fijo o de forma indefinida.

+

CAUTION: Una vez habilitada la configuración de S3 Object Lock para un bucket, no se puede deshabilitar. Cualquier persona con los permisos adecuados puede añadir objetos a este bucket que no se pueden modificar. Es posible que no puedas eliminar estos objetos ni el propio bucket.

+
${post_edited_translations.segment}

. ${post_edited_translations.segment}
+

NOTE: Tu administrador de grid debe darte permiso para link:../tenant/using-s3-object-lock.html["utilizar las funciones específicas de S3 Object Lock"].

+
Cuando la *retención predeterminada* está habilitada, los nuevos objetos que añadas al bucket se protegerán automáticamente para evitar que se eliminen o se sobrescriban. El ajuste de *retención predeterminada* no se aplica a los objetos que tienen sus propios periodos de retención.

+
.. Si la opción *Retención predeterminada* está activada, especifica un *modo de retención predeterminado* para el depósito.

 a| 
Gobernanza
 a| 
*** Los usuarios con el permiso  `s3:BypassGovernanceRetention` pueden usar el encabezado de solicitud  `x-amz-bypass-governance-retention: true` para omitir la configuración de retención.
*** ${post_edited_translations.segment}
*** ${post_edited_translations.segment}




 a| 
Cumplimiento normativo
 a| 
*** El objeto no se puede eliminar hasta que se alcance su fecha de retención.
*** ${post_edited_translations.segment}
*** La fecha de retención del objeto no se puede eliminar hasta que se alcance dicha fecha.


*Nota*: El administrador de tu grid debe autorizarte a utilizar el modo de cumplimiento.

|===
.. ${post_edited_translations.segment}
+
El *período de retención predeterminado* indica durante cuánto tiempo deben conservarse los nuevos objetos añadidos a este bucket, a partir del momento en que se ingieren. Especifica un valor que sea menor o igual al período máximo de retención para el tenant, según lo haya establecido el administrador del grid.

+
El administrador de la grid establece un periodo de retención _máximo_, que puede ser un valor de 1 día hasta 100 años, al crear el tenant. Cuando estableces un periodo de retención _por defecto_, no puede superar el valor establecido para el periodo de retención máximo. Si lo necesitas, pídele a tu administrador de la grid que aumente o disminuya el periodo de retención máximo.



. [[límite-de-capacidad]]Si lo deseas, selecciona *Activar límite de capacidad*, introduce un valor y selecciona la unidad de capacidad.
+
El límite de capacidad es la capacidad máxima disponible para los objetos de este bucket. Este valor representa una cantidad lógica (tamaño del objeto), no una cantidad física (tamaño en el disco).

+
Si no estableces ningún límite, la capacidad de este bucket es ilimitada. Consulta link:../tenant/understanding-tenant-manager-dashboard.html#bucket-capacity-usage["${post_edited_translations.segment}"] para obtener más información.

. [[object-count-limit]]Si lo deseas, selecciona *Activar límite de recuento de objetos*.
+
El límite de objetos es el número máximo de objetos que puede contener este bucket. Este valor representa una cantidad lógica (número de objetos). Si no se establece ningún límite, el número de objetos es ilimitado.

. Selecciona *Create bucket*.
+
