 a| 
Archivo de instalación de StorageGRID
 a| 
Si vas a añadir nuevos nodos de grid o un nuevo sitio, debes descargar y extraer el archivo de instalación de StorageGRID. Debes usar la misma versión que se esté ejecutando actualmente en el grid.

Para obtener más detalles, consulta las instrucciones de <<download-and-extract-install-files,descargar y descomprimir los archivos de instalación de StorageGRID>>.

*Nota:* No es necesario descargar archivos si vas a añadir nuevos volúmenes de almacenamiento a nodos de almacenamiento ya existentes o si vas a instalar un nuevo dispositivo StorageGRID.

* Cliente SSH (por ejemplo, PuTTY)

 a|

 a| 
Contraseña de aprovisionamiento
 a| 
La frase de contraseña se crea y se documenta al instalar el sistema StorageGRID por primera vez. La frase de contraseña de aprovisionamiento no está en el archivo `Passwords.txt`.

[[download-and-extract-the-storagegrid-installation-files]]
== Descarga y descomprime los archivos de instalación de StorageGRID

.[[descargar y extraer los archivos de instalación]]
Antes de poder añadir nuevos nodos de grid o un nuevo sitio, debes descargar el archivo de instalación de StorageGRID correspondiente y descomprimir los archivos.

.Acerca de esta tarea
Debes realizar las operaciones de expansión utilizando la versión de StorageGRID que se esté ejecutando actualmente en la grid.

.Pasos
. Ve a https://mysupport.netapp.com/site/products/all/details/storagegrid/downloads-tab["Descargas de NetApp: StorageGRID"^].
. Selecciona la versión de StorageGRID que se está ejecutando actualmente en el grid.
. Inicia sesión con el nombre de usuario y la contraseña de tu cuenta de NetApp.
. Lee el Acuerdo de licencia de usuario final, marca la casilla de verificación y luego selecciona *Aceptar y continuar*.
. En la columna *Instalar StorageGRID* de la página de descargas, selecciona el archivo `.tgz` o `.zip` correspondiente a tu plataforma.
+
La versión que figura en el archivo de instalación debe coincidir con la versión del software que está instalada actualmente.

+
Utiliza el archivo  `.zip` si el portátil de servicio está ejecutando Windows.

+

[[verify-hardware-and-networking]]
== Verifica el hardware y la red

Antes de comenzar la ampliación de tu sistema StorageGRID, asegúrate de lo siguiente:

* Se ha instalado y configurado el hardware necesario para dar soporte a los nuevos nodos de grid o al nuevo sitio.
* Todos los nodos nuevos tienen rutas de comunicación bidireccional con todos los nodos existentes y nuevos (un requisito para la red de grid). En particular, confirma que los siguientes puertos TCP estén abiertos entre los nuevos nodos que estás añadiendo en la expansión y el nodo de administración principal:
+
** 1055
** 7443
** 8011
** 10342


+
Consulta link:../network/internal-grid-node-communications.html["Comunicaciones internas entre nodos de grid"].

* El nodo de administración principal puede comunicarse con todos los servidores de expansión destinados a alojar el sistema StorageGRID.
* Si alguno de los nuevos nodos tiene una dirección IP de la Grid Network en una subred que no se haya utilizado antes, ya la has link:updating-subnets-for-grid-network.html["añadiste la nueva subred"] a la lista de subredes de la Grid Network. De lo contrario, tendrás que cancelar la expansión, añadir la nueva subred y volver a iniciar el procedimiento.
* No estás utilizando la traducción de direcciones de red (NAT) en la Grid Network entre los nodos de la cuadrícula o entre los sitios de StorageGRID. Cuando utilizas direcciones IPv4 privadas para la Grid Network, esas direcciones deben ser directamente enrutables desde cada nodo de la cuadrícula en cada sitio. El uso de NAT para conectar la Grid Network a través de un segmento de red pública solo se admite si utilizas una aplicación de túnel que sea transparente para todos los nodos de la cuadrícula, lo que significa que los nodos de la cuadrícula no necesitan conocer las direcciones IP públicas.
+
Esta restricción de NAT es específica de los nodos de grid y de la Grid Network. Si es necesario, puedes utilizar NAT entre clientes externos y nodos de grid, por ejemplo, para proporcionar una dirección IP pública a un Gateway Node.
