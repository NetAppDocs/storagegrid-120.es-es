= Conoce el StorageGRID bycast.log
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
El archivo  `/var/local/log/bycast.log` es el archivo principal de resolución de problemas del software StorageGRID. Hay un archivo  `bycast.log` para cada nodo de grid. El archivo contiene mensajes específicos de ese nodo de grid.

El archivo `/var/local/log/bycast-err.log` es un subconjunto de `bycast.log`. Contiene mensajes de gravedad ERROR y CRITICAL.

Si lo deseas, puedes cambiar la ubicación de destino de los registros de auditoría y enviar la información de auditoría a un servidor syslog externo. Los registros locales de auditoría se siguen generando y almacenando cuando se configura un servidor syslog externo. Consulta link:../monitor/configure-log-management.html["Configura la gestión de registros y el servidor syslog externo"].



[[file-rotation-for-bycast-log]]
== Rotación de archivos para bycast.log

Cuando el archivo  `bycast.log` alcanza 1 GB, se guarda el archivo existente y se inicia un nuevo archivo de registro.

El archivo guardado pasa a llamarse  `bycast.log.1`, y el nuevo archivo se llama  `bycast.log`. Cuando el nuevo  `bycast.log` alcanza 1 GB,  `bycast.log.1` cambia de nombre y se comprime para convertirse en  `bycast.log.2.gz`, y  `bycast.log` pasa a llamarse  `bycast.log.1`.

El límite de rotación para `bycast.log` es 21 archivos. Cuando se crea la versión número 22 del archivo `bycast.log`, se elimina el archivo más antiguo.

El límite de rotación para  `bycast-err.log` es de siete archivos.


NOTE: Si un archivo de registro se ha comprimido, no debes descomprimirlo en la misma ubicación en la que se guardó. Descomprimir el archivo en la misma ubicación puede interferir con los scripts de rotación de registros.

Si lo deseas, puedes cambiar la ubicación de destino de los registros de auditoría y enviar la información de auditoría a un servidor syslog externo. Los registros locales de auditoría se siguen generando y almacenando cuando se configura un servidor syslog externo. Consulta link:../monitor/configure-log-management.html["Configura la gestión de registros y el servidor syslog externo"].

[[messages-in-bycast-log]]
== Mensajes en bycast.log

Los mensajes en  `bycast.log` son escritos por el ADE (Asynchronous Distributed Environment). ADE es el entorno de ejecución que usan los servicios de cada nodo de la grid.

Ejemplo de mensaje ADE:

[listing]
----
May 15 14:07:11 um-sec-rg1-agn3 ADE: |12455685    0357819531
SVMR EVHR 2019-05-05T27T17:10:29.784677| ERROR 0906 SVMR: Health
check on volume 3 has failed with reason 'TOUT'
----
Los mensajes ADE contienen la siguiente información:

[cols="1a,2a"]
|===
| Segmento de mensaje | Valor en el ejemplo 


 a| 
Nodo ID
| 12455685 


 a| 
ID del proceso ADE
| 0357819531 


 a| 
Nombre del módulo
| SVMR 


 a| 
Identificador de mensaje
| EVHR 


 a| 
Hora del sistema UTC
| 2019-05-05T27T17:10:29.784677 (AAAA-MM-DDTHH:MM:SS.uuuuuu) 


 a| 
Nivel de gravedad
| ERROR 


 a| 
Número de seguimiento interno
| 0906 


 a| 
Mensaje
| SVMR: la comprobación del estado del volumen 3 ha fallado con el motivo 'TOUT' 
|===


[[message-severities-in-bycast-log]]
== Gravedades de los mensajes en bycast.log

Los mensajes en  `bycast.log` tienen niveles de gravedad asignados.

Por ejemplo:

* *AVISO* -- Se ha producido un evento que debe registrarse. La mayoría de los mensajes de registro se encuentran en este nivel.
* *ADVERTENCIA* -- Ha ocurrido una condición inesperada.
* *ERROR* -- Se ha producido un error grave que afectará las operaciones.
* *CRÍTICO* -- Se ha producido una situación anómala que ha interrumpido el funcionamiento normal. Debes solucionar el problema subyacente de inmediato.
