[[troubleshootmtualertgrid-network-mtu-mismatch-alert]]
== ${post_edited_translations.segment}

La alerta *Discrepancia en la MTU de la red Grid* se activa cuando la configuración de la unidad máxima de transmisión (MTU) de la interfaz de red Grid (eth0) varía de forma significativa entre los nodos de la grid.

.Acerca de esta tarea
Las diferencias en la configuración de la MTU podrían indicar que algunas, pero no todas, las redes eth0 están configuradas para tramas jumbo. Una discrepancia en el tamaño de la MTU superior a 1000 podría causar problemas de rendimiento en la red.

.Pasos
. El acceso externo por SSH está bloqueado de forma predeterminada. Si es necesario, link:../admin/manage-external-ssh-access.html["permitir el acceso de forma temporal"].
. ${post_edited_translations.segment}
+
** ${post_edited_translations.segment}
** Accede a `_primary Admin Node IP address_/metrics/graph` e introduce la siguiente consulta: `node_network_mtu_bytes{device="eth0"}`


. https://docs.netapp.com/us-en/storagegrid-appliances/commonhardware/changing-mtu-setting.html["Modificar la configuración de MTU"^] según sea necesario para asegurarte de que sean iguales para la interfaz de la red de grid (eth0) en todos los nodos.
+
** Para nodos basados en Linux y VMware, usa el siguiente comando: `+/usr/sbin/change-ip.py [-h] [-n node] mtu network [network...]+`
+
*Ejemplo*: `change-ip.py -n node 1500 grid admin`

+
*Nota*: en los nodos basados en Linux, si el valor de MTU deseado para la red en el contenedor supera el valor ya configurado en la interfaz del host, primero debes configurar la interfaz del host para que tenga el valor de MTU deseado y luego usar el script `change-ip.py` para cambiar el valor de MTU de la red en el contenedor.

+

No puedes configurar los parámetros de FEC en los dispositivos StorageGRID. En su lugar, los dispositivos intentan detectar y replicar los parámetros de FEC de los puertos del switch a los que están conectados. Sin una configuración FEC común, la red pasará al modo "sin FEC". Cuando la FEC no está habilitada, las conexiones son más susceptibles a errores causados por el ruido eléctrico.

No es necesario que los valores de MTU sean iguales para todos los tipos de red. Consulta <<troubleshoot_MTU_alert,${post_edited_translations.segment}>> para más información.

[[linux-network-connectivity-issues]]
== ${post_edited_translations.segment}

Es posible que veas problemas de conectividad de red en los nodos de StorageGRID alojados en hosts Linux.



[[mac-address-cloning]]
=== ${post_edited_translations.segment}

En algunos casos, puedes resolver los problemas de red usando la clonación de direcciones MAC. Si usas hosts virtuales, establece el valor de la clave de clonación de direcciones MAC para cada una de tus redes en "true" en tu archivo de configuración del nodo. Esta configuración hace que la dirección MAC del contenedor de StorageGRID use la dirección MAC del host. Consulta las instrucciones para link:../swnodes/creating-node-configuration-files.html["${post_edited_translations.segment}"].


NOTE: Crea interfaces de red virtuales independientes para que las use el sistema operativo host de Linux. Si usas las mismas interfaces de red para el sistema operativo host de Linux y el contenedor de StorageGRID, el sistema operativo host podría quedar inaccesible si no has habilitado el modo promiscuo en el hipervisor.

Para obtener más información, consulta las instrucciones de link:../swnodes/configuring-host-network.html["activar la clonación de direcciones MAC"].



[[promiscuous-mode]]
=== Modo promiscuo

Si no deseas utilizar la clonación de direcciones MAC y prefieres permitir que todas las interfaces reciban y transmitan datos para direcciones MAC distintas de las asignadas por el hipervisor, asegúrate de que las propiedades de seguridad a nivel de conmutador virtual y de grupo de puertos estén configuradas en *Aceptar* para el modo promiscuo, los cambios de dirección MAC y las transmisiones falsificadas. Los valores configurados en el conmutador virtual pueden ser anulados por los valores a nivel de grupo de puertos, así que asegúrate de que la configuración sea la misma en ambos lugares.

Para obtener más información sobre cómo utilizar el modo promiscuo, consulta las instrucciones para link:../swnodes/configuring-host-network.html["Cómo configurar la red del host"].



[[linux-node-status-is-orphaned]]
== Linux: el estado del nodo es «huérfano»

Un nodo de Linux en estado «huérfano» suele indicar que, o bien el servicio storagegrid o bien el demonio del nodo StorageGRID que controla el contenedor del nodo se ha detenido de forma inesperada.

.Acerca de esta tarea
Si un nodo de Linux indica que se encuentra en estado huérfano, debes:

* Comprueba los registros en busca de errores y mensajes.
* ${post_edited_translations.segment}
* ${post_edited_translations.segment}
* ${post_edited_translations.segment}


.Pasos
. ${post_edited_translations.segment}
. Inicia sesión en el host como root o usando una cuenta con permisos sudo.
. Intenta volver a iniciar el nodo ejecutando el siguiente comando: `$ sudo storagegrid node start node-name`
+
 $ sudo storagegrid node start DC1-S1-172-16-1-172
+
Si el nodo queda huérfano, la respuesta es

+
[listing]
----
Not starting ORPHANED node DC1-S1-172-16-1-172
----
. En Linux, detén el motor de contenedores y cualquier proceso storagegrid-node que esté controlando. Por ejemplo:``sudo docker stop --time secondscontainer-name``
+
En `seconds`, introduce el número de segundos que quieres esperar a que se detenga el contenedor (normalmente 15 minutos o menos). Por ejemplo:

+
[listing]
----
sudo docker stop --time 900 storagegrid-DC1-S1-172-16-1-172
----
. Reinicia el nodo: `storagegrid node start node-name`
+
[listing]
----
storagegrid node start DC1-S1-172-16-1-172
----




[[linux-troubleshoot-ipv6-support]]
== Linux: Soluciona problemas de compatibilidad con IPv6

${post_edited_translations.segment}

.Acerca de esta tarea
Para ver la dirección IPv6 que se ha asignado a un nodo de la red:

. ${post_edited_translations.segment}
. Selecciona *Mostrar direcciones IP adicionales* junto a *Direcciones IP* en la pestaña *Resumen*.


Si no se muestra la dirección IPv6 y el nodo está instalado en un host Linux, sigue estos pasos para habilitar la compatibilidad con IPv6 en el kernel.

.Pasos
. Inicia sesión en el host como root o usando una cuenta con permisos sudo.
. Ejecuta el siguiente comando: `sysctl net.ipv6.conf.all.disable_ipv6`
+
[listing]
----
root@SG:~ # sysctl net.ipv6.conf.all.disable_ipv6
----
+
El resultado debería ser 0.

+
[listing]
----
net.ipv6.conf.all.disable_ipv6 = 0
----
+

NOTE: Si el resultado no es 0, consulta la documentación de tu sistema operativo para cambiar la configuración de  `sysctl`. Luego, cambia el valor a 0 antes de continuar.

. Accede al contenedor del nodo de StorageGRID: `storagegrid node enter node-name`
. Ejecuta el siguiente comando: `sysctl net.ipv6.conf.all.disable_ipv6`
+
[listing]
----
root@DC1-S1:~ # sysctl net.ipv6.conf.all.disable_ipv6
----
+
${post_edited_translations.segment}

+
[listing]
----
net.ipv6.conf.all.disable_ipv6 = 1
----
+

NOTE: Si el resultado no es 1, este procedimiento no es aplicable. Ponte en contacto con el soporte técnico.

. Sal del contenedor: `exit`
+
[listing]
----
root@DC1-S1:~ # exit
----
. Como root, edita el siguiente archivo: `/var/lib/storagegrid/settings/sysctl.d/net.conf`.
+
[listing]
----
sudo vi /var/lib/storagegrid/settings/sysctl.d/net.conf
----
. Localiza las siguientes dos líneas y elimina las etiquetas de comentario. A continuación, guarda y cierra el archivo.
+
[listing]
----
net.ipv6.conf.all.disable_ipv6 = 0
----
+
[listing]
----
net.ipv6.conf.default.disable_ipv6 = 0
----
. ${post_edited_translations.segment}
+
[listing]
----
storagegrid node stop node-name
----
+
[listing]
----
storagegrid node start node-name
----
